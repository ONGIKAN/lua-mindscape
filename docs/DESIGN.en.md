# Lua Mindscape — Design Notes

> Design model, trace protocol, visual encoding, and production architecture for
> "Lua thought visualizer". Chinese version: [DESIGN.md](DESIGN.md). Prototype code: `app.js`.

## 1. Problem & goal

The idea: *a Lua runtime that shows the AST live, so you can watch a program think.* Decomposed:

- **Live**: the picture follows execution step by step (not a static render after the fact);
- **AST**: execution happens *on the tree* — the order in which nodes light up is the evaluation order;
- **Cross-platform**: desktop, tablet, phone;
- **Stack preference**: Rust + Lua.

Core judgement: **a static AST is only the skeleton; what feels like "thinking" is the evaluation
trace projected onto the AST.** The AST answers "what does the program look like"; the trace answers
"what is the program doing right now". So the product is not a tree drawing —
it is *projecting the interpreter's event stream onto tree, source, and stack frames in real time*.

## 2. Layered model

```
source text
  │  parse (spans preserved)
  ▼
AST (structure)
  │  run (explicit state machine, emitting events)
  ▼
TraceEvent[] (trace)
  │  seek / play (fold a prefix to get state at time t)
  ▼
RuntimeState (state) → render (tree / source / frames / output)
```

- **Structure**: every node has `id`, kind `k`, source span `[start,end)`, children.
- **Trace**: the interpreter emits events while evaluating; events reference node ids.
- **State**: folding an event prefix yields current node, path, frames, bindings, evaluated set.
  Rendering reads only this state — **playback and rendering are decoupled**, which is why the
  timeline can jump anywhere.

## 3. Trace event protocol

Events are plain data (production: defined in Rust, TypeScript types generated by `ts-rs`).

| Event | Meaning | Key fields |
| --- | --- | --- |
| `ent` | enter a node | `id, k, span` |
| `cls` | finish a node | `id` |
| `val` | expression result | `id, v` |
| `set` | binding/assignment | `name, v, f` |
| `call` | function call (new frame) | `id, name, nf, argc` |
| `ret` | return (pop frame) | `id, name, v` |
| `iter` | loop iteration | `id, name, v` |
| `print` | program output | `text` |
| `end` | program finished | — |
| `error` | runtime error | `message` |

Every event originates from «a frame + a node + a moment», so all panels can highlight in sync.

## 4. Visual encoding

| Visual | Meaning | Rationale |
| --- | --- | --- |
| Box + ring + halo | current node | One focus at a time; a ring occludes less text than a fill |
| Solid indigo edge | path root → current node | Makes "the way the thought got here" visible |
| `= value` on the right | computed value | Data flow becomes visible, not just control flow |
| Color | stack frame | Recursion has several live contexts; color is the one channel that encodes all at once |
| `×n` | repetition count | Loop/recursion hotspots at a glance |
| Table color dot | object identity | Aliasing is nearly invisible in text |
| Highlighted code line | current node / caller frame | Maps tree position back to source |

Style: light, square, thin borders, one accent color — a *teaching dashboard*, not a tech promo.

## 5. Interaction

- **Timeline first**: play, pause, step, scrub; any moment is fully reconstructable.
- **The tree is a timeline**: click any node to jump to its next execution event.
- **Editable code**: the source pane can be edited and run (prototype uses a highlighted layer plus a
  transparent textarea, keeping syntax colors and caret alignment); parse errors are shown inline.
- **New / import**: `+ New` creates a template; `Import` picks a `.lua` file (or drag it onto the
  code pane) and compiles/runs it immediately; parse errors are shown inline.
- **Camera (fit-the-tree + dead zone)**: on load/run the whole tree is scaled to fit and centered;
  during playback it stays completely still while the current node is inside the viewport, and snaps
  once only when the node would leave. Clicking a node, zooming or `⤢` re-centers. Panning/zooming
  pauses follow; on small screens the active code line is scrolled into view.
- **Bilingual**: UI strings and node kind names come from an i18n dictionary; `EN / 中` persists.

## 6. Layout & rendering

- Three panes: source / tree / runtime state; single column below 980px.
- Tree layout: classic tidy tree (leaves take rows, parents at children's midpoint), with extra
  spacing between sibling subtrees so branches from different parents do not visually merge.
- Rendering: DIV nodes + SVG cubic edges; update classes/text only, never rebuild the DOM.
- Camera: direct `translate + scale`, static layout coordinates.

## 7. Performance budget (production)

| Metric | Target |
| --- | --- |
| Single-step render | < 4ms (only changed nodes) |
| Scrubbing | nearest checkpoint + replay ≤ a few hundred events |
| Event size | < 100B each; sampling/folding for long loops |
| Large trees | render only the visible region; collapse statements |

## 8. Production architecture

- **Parser**: Rust `full-moon` (lossless AST + spans, Lua 5.4).
- **Interpreter**: our own explicit state machine — **no line-hook instrumentation** of a real Lua VM
  (debug hooks are line-granular and cannot produce node-level events). Semantic risk is covered by
  **differential testing against `mlua`**.
- **Transport**: WASM + `ts-rs`-generated types.
- **Frontend**: TypeScript + a lightweight framework (Solid / Svelte candidates), SVG/DOM rendering,
  Canvas fallback.
- **Packaging**: Tauri 2 for desktop + mobile sharing one frontend; the web version is installable
  as a PWA (already implemented in the prototype).

## 9. Testing strategy

- **Semantics**: assertions on the three samples (30 / 6 / 12); randomized differential tests vs mlua.
- **UI**: `tools/qa.mjs` (headless Edge + CDP) checks layout, event counts, active node, frame count,
  screenshots; regression at phone / tablet breakpoints.
- **Editor**: custom code runs, parse errors, localStorage restore.
- **i18n**: full-string assertions with `?lang=en`.

## 10. Decisions / open questions

Decided:
1. The trace is the product core; the AST is the carrier.
2. Own explicit-state interpreter + differential tests, instead of hooking a real VM.
3. Rust → WASM core; Tauri 2 shell for desktop/mobile.
4. Light, square, minimal visuals; SVG/DOM rendering.

Open:
- Adopt CodeMirror 6 for the production editor;
- Sampling/snapshot parameters for the event stream;
- Staged coverage for coroutines / metatables.
